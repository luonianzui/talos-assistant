# 塔罗斯本地打牌助手

Windows 简体中文桌面工具。提供「平均收益」和「冲顶级」策略、本地画面识别、手动校正、局面保存及回放。程序不上传截图或局面，不自动点击游戏。

在其他电脑或云端继续开发时，先阅读 [项目接续说明](HANDOFF.md)，其中记录当前进度、验证范围和下一步工作。

**当前为可运行的校验版。** 已实现的规则与未实现范围见 `data/rules_reference.json`。尚未获得用户实机截图/完整对局，因此不能声称已通过实服整局验证、覆盖完整赛季卡池或实现所有局面的全局最优。未知效果、隐藏概率、未来巡监和未展示的奖励会使数值推演停止，界面会明确说明。

## 启动

解压便携包，运行 `TalosAssistant.exe`。保留旁边的 `_internal` 文件夹。用户端无需 Python、API 密钥或联网；校准数据和会话保存在旁边的 `user_data`。

源码启动：

```powershell
.venv\Scripts\python.exe run.py
```

开发环境需要 Python 3.12 x64：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev]"
.venv\Scripts\python.exe tools\fetch_models.py
.venv\Scripts\python.exe run.py
```

`fetch_models.py` 仅在开发/打包时下载官方 RapidAI PP-OCRv4 模型并校验 SHA256；应用运行过程中不调用它，也不自动下载模型。使用 Windows 已安装的本地字体。

## 第一次使用

1. 点击「示例局面」检查界面和计算；「两种策略如何选择？」说明合成场景下两种目标的差别。示例概率不是游戏掉率。
2. 在「画面识别与校准」选择游戏窗口或导入截图。游戏应处于窗口/无边框模式且棋盘可见，助手不能遮挡棋盘。
3. 选择「整个棋盘」后拖拽框选。默认采用 6×4 外环的 16 个位置，0 号为办公室，顺时针编号。也可选择 4×4 网格或单格校准。
4. 分别框选天数、绮彩累计、当前位置、效果栏及本日操作相关区域。只有剩余天数时选择「剩余天数」，不要误设为当前天数。
5. 如果图标未识别，选择「样本牢房」并点击「学习该格图标」，人工填写代号、品质和牢房状态。为不同类型/品质添加真实样本。工具不附带虚构的游戏模板。
6. 点击「识别这一帧」或「开始自动读取」。自动读取要求两帧稳定、只处理新画面。核对并修正棋盘、计数和效果后点击「确认已校正本次识别」。
7. 阅读「规则与数据」并核对规则配置。当前有巡监目的地时通过「巡监候选」填写实际选项。
8. 选择策略并分析。操作游戏后重新读取；识别不清的字段和不支持的效果不能通过勾选核对变成已知规则。

当前识别器尚不能读取特殊标记：每次识别后需在各牢房编辑器中逐格核对标记（没有则保存空数组），再填写当前巡监选项。采集或识别失败会停止自动读取，并将旧值标为待核对；重新读取或人工完整确认后再分析。动画期间立即撤下旧建议，两帧稳定后才启动下一次识别。

## 两种策略

- **平均收益**：最大化最终绮彩数量期望，相同收益优先较少操作。
- **冲顶级**：寻找至少有指定概率达到的最高绮彩数量。默认最低达成率 20%，再比较达成率及平均数量。提高门槛更稳妥，降低门槛更进取。

例如，稳定获得 2 个与 30% 获得 5 个/70% 获得 0 个相比：平均收益偏好前者，20% 门槛的冲顶级偏好后者。这个例子只解释策略。

每次切换保留棋盘，取消旧任务并重算。计算预算默认初步 2 秒、总计 10 秒；只有在规则、概率和所有分支足够完整时才输出终局分布。未知概率不默认为等概率，截断局面的启发分数也不冒充最终绮彩数量。

## 局面与回放

「保存 / 导出」包含整局观察快照。「导入 / 回放」可查看任一快照并采用它继续分析。重复画面不会累计奖励；绮彩数是读取的绝对计数。

当前导入本工具的 `talos.assistant.session.v1` 或 `GameState` JSON。网页模拟器导出的规则与结构不同，不直接混用。

「刑具 / 事件 / 珍藏」使用可编辑 JSON：`effects` 为全局效果，`treasures` 为当前道具，`pending_options` 为待处理结果；牢房标记在单格编辑器中填写。支持的 id、参数及来源均在规则页。未收录效果可保留为未知项，工具会暂停计算而非忽略它。

概率模型需明确来源；没有可靠统计时保持空表。当前 `species` 表用于代号变化，`ranks` 表共用于开门与换人；只有确认该模型适用于当前局面时才使用。后续应按实测拆分更多条件分布。

## 检查与打包

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe benchmarks\solver_benchmark.py
.venv\Scripts\python.exe tools\smoke_app.py
.venv\Scripts\python.exe -m PyInstaller --noconfirm TalosAssistant.spec
dist\TalosAssistant\TalosAssistant.exe --self-test artifacts\selfcheck-packaged.json
.venv\Scripts\python.exe tools\package_release.py
```

测试覆盖规则转移、策略分歧、状态/模式过期结果过滤、重复观察、导入校验、合成画面稳定判定与图标匹配。合成画面测试不能替代实机识别准确率验证。

`--self-test` 使用临时数据目录与合成中文图片，不读取真实游戏窗口，禁止 Python socket 连接并记录尝试次数；验证界面、策略切换、模型加载和 OCR，输出 JSON 与同目录 `preview.png`。这项自检不等同于断网完成实机整局。

打包配置使用 Windows 自带 ICU，排除构建机 PATH 中可能混入的 Poppler ICU；两者虽同名，但导出符号不同，会导致 Qt 无法启动。便携版启动日志位于 `user_data/startup.log`。压缩包不包含用户数据。

源码与运行包为独立实现，没有复制第三方模拟器代码或游戏素材。依赖和 OCR 模型的来源见 `THIRD_PARTY.md` 与 `models/provenance.json`。
